## Question 2: What Database Did You Use, and Why?
**Answer:**  
We used **MongoDB** for our database. Here's why we chose MongoDB over a traditional relational database like MySQL:
1. **Flexible Schema Design**: Our menu items can have varying attributes (e.g., some items have size options, some have nutrition info, others don't). MongoDB's document-based structure lets us store this data easily without strict table schemas.
2. **Easy Integration with Node.js**: MongoDB integrates seamlessly with our Node.js backend using Mongoose (an Object Data Modeling library for MongoDB), making development faster and simpler.
3. **Scalability**: If the business grows and we need to handle more users and orders, MongoDB can scale horizontally, which is perfect for future expansion.
4. **Real-time Capabilities**: For features like real-time order updates (which we plan to add later), MongoDB works well with real-time libraries.

We use Mongoose schemas to enforce data consistency and validation, so we still have structure where we need it!

## Question 3: What Algorithms Did You Use in Your System?
**Answer:**  
We implemented several key algorithms in our system:
1. **Password Hashing with Bcrypt**: We use the bcrypt algorithm to securely store user passwords. Bcrypt is an adaptive hashing algorithm that's slow and resistant to brute-force attacks. It automatically handles salting (adding random data to passwords before hashing), so even if two users have the same password, their hashes will be different.
2. **Search and Filtering Algorithm**: For menu item search, we use MongoDB's `$regex` with case-insensitive option on the server-side, and JavaScript's `filter()` and `includes()` methods on the client-side for real-time filtering as the user types.
3. **Cart Management Algorithm**: We use a JavaScript object (hash map) to store cart items, which gives us O(1) average time complexity for add, remove, and update operations. To calculate the total price, we use the array `reduce()` method, which is O(n) time complexity (n = number of items in the cart).
4. **Input Validation & Sanitization**: We validate inputs on both client-side (for better UX) and server-side (for security) using simple regex checks and type validation, along with Mongoose schema validation to ensure data integrity and prevent security vulnerabilities like NoSQL injection.

## Question 4: What Security Measures Did You Implement?
**Answer:**  
We take security seriously! Here are the security measures we implemented:
1. **Password Hashing**: As I mentioned earlier, we use bcrypt to hash all user passwords. We never store plain text passwords in the database.
2. **Input Validation & Sanitization**: We validate all user inputs on both client and server side to prevent malicious data from being stored or processed. This helps prevent attacks like NoSQL injection and XSS (Cross-Site Scripting).
3. **Environment Variables**: We store sensitive information (like our database URI and email credentials) in environment variables using `config.env`, and we never commit this file to GitHub (it's in our `.gitignore`).
4. **Role-Based Access Control (RBAC)**: Our system has different user roles (Admin, Staff, Customer), each with different permissions. For example, only admins can manage menu items and user accounts, and staff can only manage orders.
5. **JWT Authentication**: We use JSON Web Tokens (JWT) for user authentication, so each request is authenticated, and only authorized users can access protected routes.
6. **Secure Email Communication**: For password recovery, we use Nodemailer with secure SMTP settings to send OTP codes to users' email addresses.
