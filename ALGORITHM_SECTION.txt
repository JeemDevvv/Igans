Algorithm
The Web-Based QR Code and Location-Based Restaurant Ordering System with AI Food Recommendation implements a comprehensive set of algorithms to streamline the restaurant ordering process. These algorithms handle customer onboarding via QR codes, location verification to ensure physical presence, intelligent food recommendations, and efficient order management through the admin panel. Each algorithm is designed to be user-friendly, secure, and efficient, ensuring that both customers and restaurant staff can interact with the system seamlessly. The following algorithms outline the core functionalities of the system, from the moment a customer scans a QR code to the final serving of the order.

1. QR Code Table Mapping Algorithm
This algorithm enables customers to scan a table-specific QR code, extract the table information, and lock their order session to that particular table.
Inputs: Scanned QR code data (URL containing table number parameter), Session storage
Outputs: Table number stored in session, Customer redirected to location verification page, Session locked to specific table
Step-by-step:
Step 1: Start
Step 2: Customer scans table QR code using mobile device camera
Step 3: Browser opens the QR code URL (verify.html?table=N)
Step 4: System extracts table number from URL query parameter
Step 5: Table number is saved to browser session storage
Step 6: Table number chip is displayed on verification page
Step 7: System redirects customer to location verification step
Step 8: Order session is now locked to the scanned table number
Step 9: End
This ensures all orders from the customer are automatically associated with the correct table, eliminating order mix-ups.

2. Geofencing/Location Verification Algorithm
This algorithm verifies whether a customer is physically inside or within the allowed radius of the restaurant before allowing them to proceed with placing an order.
Inputs: User's GPS latitude/longitude coordinates, Restaurant GPS coordinates, Allowed radius (in meters)
Outputs: Access granted (redirect to menu) or access denied (error message)
Step-by-step:
Step 1: Start
Step 2: Customer clicks "Verify My Location" button
Step 3: System requests location permission from browser
Step 4: System fetches restaurant coordinates and allowed radius from server settings
Step 5: Browser retrieves user's GPS coordinates with high accuracy
Step 6: Calculate distance between user and restaurant using Haversine formula
Step 7: IF distance ≤ allowed radius THEN
    → Show success message: "Location verified!"
    → Redirect customer to order type selection page
Step 8: ELSE
    → Show error message with distance calculation
    → Deny access to ordering system
    → Allow customer to try verification again
Step 9: User coordinates and distance are displayed for transparency
Step 10: End
This ensures only customers physically present at the restaurant can place orders, preventing remote or unauthorized ordering.

3. AI Food Recommendation Algorithm (LLM-Powered with Fallback)
This algorithm uses GROQ AI (Llama 3.3 70B) for natural language food recommendations, with a built-in keyword/preference-based fallback system for reliability.
Inputs: User message (natural language), Chat history, Available menu items, GROQ API key
Outputs: AI-generated food recommendations, Optional ADD_TO_CART action, Fallback recommendations if AI fails
Step-by-step:
Step 1: Start
Step 2: Customer types message or selects suggestion in AI chat
Step 3: System receives user message and session ID
Step 4: System checks if GROQ API key is valid and available
Step 5: IF GROQ API is available THEN
    → Load all available menu items from database
    → Format menu as context for AI: "Item Name (₱Price): Description"
    → Load last 6 messages from chat history for context
    → Send request to GROQ Llama 3.3 70B model with system prompt
    → System prompt includes: friendly tone, Taglish/English response, menu context, ADD_TO_CART command rules
    → Set temperature: 0.5, max_tokens: 300 for focused responses
    → Receive AI-generated reply
    → Parse reply for [COMMAND:ADD_TO_CART:ITEM_NAME] tags
    → Remove command tags from final user-facing reply
    → Save interaction to chat log
    → Return AI reply and action to frontend
    → Mark as success
Step 6: ELSE (GROQ API fails, token runs out, or API key missing)
    → Fallback to keyword/preference-based system
    → Parse user message for intent keywords: spicy, affordable, drinks, chicken, beef, rice, etc.
    → Use regex patterns to detect: greetings, buy requests, availability questions, confirmations, done messages
    → Match keywords against menu item names and descriptions
    → Filter and sort available menu items
    → Select top 3 recommendations
    → Format fallback response with item names, prices, and descriptions
    → Save interaction to chat log
    → Return fallback reply
Step 7: End
This hybrid approach ensures the chatbot is always available, even when the GROQ AI service is unavailable or tokens are exhausted.

4. Admin Order Management and Status Update Algorithm
This algorithm allows kitchen staff and administrators to receive incoming orders, view order details, update order statuses, and maintain a real-time order queue.
Inputs: New order data (items, table number, total, special requests), Selected status update (pending, preparing, ready, served, cancelled)
Outputs: Order status updated in database, Real-time order list refreshed, Status change notification shown
Step-by-step:
Step 1: Start
Step 2: System loads all orders from database sorted by newest first
Step 3: Admin/kitchen staff views order queue on dashboard
Step 4: Staff selects an order to view details (items, table, total, special requests)
Step 5: Staff selects a new status from dropdown menu
Step 6: System validates if status change is allowed
Step 7: IF current status is "served" or "cancelled" THEN
    → Disallow further status changes
Step 8: ELSE
    → Update order status in database
    → Record timestamp of status update
    → Show success toast notification
    → Refresh order list to reflect changes
Step 9: Order progress is updated for both staff and customer
Step 10: Customer sees real-time status update on their order status page
Step 11: End
This creates a smooth workflow from order placement to serving, with full transparency for both staff and customers.
